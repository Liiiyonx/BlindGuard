# BlindGuard 模型重训练指南

> 结论先行：当前 best.pt 的三个问题（行人被误检为 car、前景手套被误检为 bicycle、
> 井盖/盲道漏检）全部指向**训练数据**，不是算法。重训一次即可解决，工作量主要在采集标注。

## v3 全新训练（2026-09，进行中/已完成见 evaluation/metrics_report.md）

应"彻底重做、不基于旧模型"的要求，v3 与旧 best.pt **零关联**：
- 数据：COCO train2017 全量选择性抽取 **35,000 张**（v2 用 2,926 张的 12 倍）+ val2017 3,001 张验证
- 类别：**7 类**（person/bicycle/car/motorcycle/bus/truck/traffic_light）——新增摩托车/公交/卡车
- 起点：COCO 官方预训练 yolov10n.pt（非旧 best.pt）
- 训练：RTX 5060，imgsz 640，batch 32，20 epochs，约 2.2 小时
- 工具链：`build_dataset_v3.py`（6 分段虚拟拼接读取，免解压省 20GB 磁盘）+ `train.py`

**定制类（井盖/盲道/公共设施）最终结论**：全网（HF/GitHub/镜像站）无可直接下载的检测数据集。
GitHub 上确有井盖 1 万张（Good/Broke/Lose/Uncovered/Circle 状态标注，VOC/YOLO 格式，
见 QQ767172261 的仓库 README）与多个盲道项目，但数据本体在 CSDN 积分下载/百度网盘，
需手动获取后并入训练。在此之前，部署管线保留 best.pt 作白名单辅助模型兜底这三类。

## 双模型分工（2026-09 已上线）

调研结论：**井盖/盲道/公共设施没有可用的公开检测数据集**
（HF 全网仅一个井盖分类集，旧模型在其特写图上定位成功率仅 0.7%，无法转为训练对），
硬训 7 类会因样本稀缺导致这三类灾难性遗忘。因此实施双模型分工：

| 角色 | 模型 | 负责类别 | 数据 |
|---|---|---|---|
| 主模型 | COCO 预训练 yolov10n → **GPU 领域微调**（`data_blindguard_4class.yaml`，2926 张 COCO val2017 真值） | person / car / bicycle / traffic light | COCO 真值标注 |
| 辅助模型 | 原 best.pt（类别白名单过滤） | manhole_cover / public_facility / tactile_paving | 原自训数据 |

双模型合并规则（app.py `_merge_detections`）：主模型优先，辅助模型仅按白名单输出定制类、
且与主模型同类别框 IoU>0.55 时去重——旧模型的 person→car、手套→bicycle 误检被白名单直接拦截。
实测 RTX 5060 上双模型共 28.8ms/帧（≈35 FPS）。

**定制类的长期解法不变**：按下方流程自采第一人称数据标注后，训练统一 7 类模型替换双模型。

## 一、为什么要重训（评测证据）

见 `evaluation/metrics_report.md` 抽检结论：
1. **缺"行人"类**：模型只有 6 类，行人被硬塞进最像的 car/bicycle——行人恰是导盲最高频目标；
2. **域差距**：训练数据为横屏相机视角，部署为竖屏第一人称手机视角（手套/衣袖/盲杖入镜）；
3. **小目标细节不足**：井盖/盲道是地面小目标，imgsz=640 下竖屏构图细节大量丢失。

## 二、新类别定义（7 类）

沿用原 6 类的类别 ID 顺序（保持兼容），末尾新增 person：

```yaml
# data_blindguard_v2.yaml —— 放在项目根目录，path 指向数据集根目录
path: dataset/blindguard_v2
train: images/train
val: images/val

names:
  0: car
  1: bicycle            # 两轮非机动车（含电动自行车）
  2: manhole_cover
  3: public_facility
  4: tactile_paving
  5: traffic_light
  6: person             # 新增：行人（导盲最高频目标）
```

> 代码侧无需任何修改：config.yaml 的 risk_engine 与 class_mapping 都是按名字匹配的，
> person 已在中等风险类与中文映射里。

## 三、数据采集规范（目标 ~1800 张，1-2 天工作量）

| 类别 | 目标张数 | 采集要点 |
|---|---|---|
| person | 300+ | 各种距离/衣着/背光/背影，含拉行李、推车姿态 |
| manhole_cover | 300+ | **最难类**：不同俯角、干湿路面、阴影、圆形/方形 |
| car | 200+ | 第一人称近距视角为主（现有短板） |
| bicycle | 200+ | 明确含电动自行车；行驶+停放 |
| tactile_paving | 200+ | 条带完整段+破损段 |
| traffic_light | 150+ | 横竖构图都要 |
| public_facility | 150+ | 护栏、灯杆、配电箱等 |
| 负样本（不标注） | 100-150 | 含手套/衣袖/盲杖/纯路面——**这是压误检的关键** |

**采集方式（按优先级）**：
1. 手机直接实拍第一人称视角（与部署形态一致，不要录屏！）；
2. 让志愿者手持盲杖/戴手套入镜拍摄（覆盖 OOD 前景）；
3. 现有视频可用 `python evaluate.py bootstrap` 抽帧打底，但注意录屏失真只作补充。

**标注工具**：labelImg（YOLO 格式）或 CVAT / Roboflow。
标注规范：遮挡/截断目标照常标注可见部分；井盖框含完整边缘；盲道按连续条带整段标注；
最小目标 10px 以下不标；负样本图片零标注文件留空。

**数据划分**：train/val ≈ 8:2，同一场景的帧不要同时跨 train 和 val。

## 四、训练

```bash
# 有 NVIDIA 显卡（推荐，1500 张 960px 约 2-4 小时）
python train.py --data data_blindguard_v2.yaml --device 0

# 无显卡：用免费云端 GPU（Google Colab / Kaggle），上传数据集后同样命令
# 实在只能本机 CPU：减小规模 --imgsz 640 --epochs 80
```

## 五、验收标准（不达标不要上线）

在验证集（`evaluate.py accuracy --data data_blindguard_v2.yaml`）上：

| 类别 | AP@0.5 达标线 |
|---|---|
| person | ≥ 0.80 |
| car | ≥ 0.85 |
| manhole_cover | ≥ 0.70 |
| tactile_paving | ≥ 0.75 |
| 其余 | ≥ 0.70 |

再过一道**实拍抽检**：`python evaluate.py collect` 对新视频采样，人工抽检精确率 ≥ 0.70
（当前模型约 0.13，这是最直观的前后对比证据）。

## 六、上线与回滚

```bash
copy best.pt best_backup.pt        # 1. 备份
copy runs/detect/blindguard_v2/weights/best.pt best.pt   # 2. 替换
python smoke_test.py               # 3. 冒烟验证
python evaluate.py collect         # 4. 实拍复检
# 回滚：copy best_backup.pt best.pt
```

## 七、常见坑

- **类别 ID 顺序必须与 yaml 一致**，train.py 会按 names 解析；
- 训练曲线如果 val mAP 早停后仍上涨说明数据不够多样，补数据而非加轮数；
- 误检集中在某类（如手套→bicycle）就补该场景负样本，不要盲目调阈值；
- 上线后立刻跑一遍 `evaluate.py collect` 人工抽检留档，作为答辩的"优化前后对比"证据；
- **国内网络训练前置检查**：ultralytics 启动时会静默下载 yolo11n.pt（AMP 检查），GitHub 在
  Python 侧可能长时间挂起——提前 `curl -LO https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11n.pt`
  放到项目根目录；训练输出用 `python -u ... > training.log 2>&1` 直写文件以便监控；
- **PyTorch 必须装 CUDA 构建**：`pip install` 默认给 CPU 版（`torch.cuda.is_available()=False`）。
  RTX 50 系（Blackwell）需 cu128 轮子：
  `python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128`，
  国内可用 curl 直下轮子后 `pip install --no-index --no-deps <wheel>` 离线安装。
