智能体：编排式专业团队 + 确定性安全守门员

  • 本地意图路由覆盖 7 类意图，进入模型前最多预取 2 个本地只读工具
  • LLM 角色规划：规则未命中（intent=general）时由模型做任务分解，只决定参与角色与理由；只决定角色、不决定工具，工具由角色表推导，证据与实际执行天然一致。通行问题 / 路由关闭 / 已降级时一律不规划，规划调用独立超时且不计入熔断，失败静默回落规则计划
  • 角色执行：主责与协作角色（最多 3 个）各执行 1 个只读工具，产出结构化结论写入 role_contributions
  • 工具注册表统一做 JSON Schema 校验、读写权限、安全级别、超时控制与最近 100 次调用审计
  • 模型工具预算：最多 3 轮、累计 6 次；写工具仅限偏好意图，外部视觉仅限明确视觉意图，每次对话最多 1 次
  • 阶段轨迹：routing → prefetch → specialists → llm → tool_loop → safety_review，标记缓存命中、策略拒绝与运行路径
  • 模型中途不可用时如实标注「本地兜底」，不把模板回答包装成模型作答

安全：确定性护栏，模型没有通行授权权

  • 红灯 / 黄灯 / 未知灯色 / 无可靠检测 / 高风险场景 绕过模型，本地直接拒绝，不等网络
  • 绿灯不等于通行许可；静默不等于安全；漏检不等于安全
  • 回复中出现「可以通行 / 放心走」类授权措辞会被整句拦截替换，且二次复核幂等
  • 改写动作可审计并上屏：原样返回 / 追加保守说明 / 整句替换，附原始回复与最终回复对照
  • 拒绝授权 ≠ 拒绝帮助：拒绝通行之后仍给出方位与避障建议，但不含任何过街授权

诚实边界：这些还没有验证，我们不外推

  • 当前部署配置的端到端实拍准确率尚未统计 —— 标注与统计工具已就绪（evaluate.py e2e-init / e2e，含主辅双模型、裁剪、合并与灯色），缺的是人工校正样本；上表 mAP 与灯色准确率均为离线口径，不代表现场表现

  • 真实路口零错误授权验收未完成，需陪护在受控道路执行
  • 在线模型当前账户余额不足（HTTP 402），现场用本地 qwen2.5:3b 验证协议与闭环
  • 多模态看图未配置视觉端点，能力已就绪但未做设备验证

因此我们不声称「真实准确率 90%+」「已通过视障用户验证」「可替代盲杖」。 本系统是辅助感知工具，不是安全认证设备：输出的是提示而非指令。
