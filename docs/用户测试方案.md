# BlindGuard 用户测试方案（志愿者内测 · 第一轮）

> 目的：回答评委与产品都必须回答的问题——"视障用户真的能用吗？"
> 第一轮只求定性发现，不求统计显著性。5-8 位用户即可。

## 1. 招募

- 渠道：当地盲人协会、特教学校、社区残协；每位用户可带 1 名陪护
- 人数：视障用户 5-8 人（全盲 ≥3，低视力 ≥2），可加 2-3 名蒙眼体验者作对照
- 伦理：签署知情同意；全程一对一陪护；随时可终止；蒙眼体验者必须在安全场地

## 2. 场景分级（由易到难，用户可随时停止）

| 阶段 | 场景 | 验证目标 |
|---|---|---|
| A | 室内桌面，手机/摄像头对准桌面物品 | 语音能否听清、语速是否合适 |
| B | 封闭走廊 / 无障碍园区道路 | 播报是否及时、是否会嫌吵 |
| C | 真实人行道（陪护保护） | 红绿灯、井盖、盲道提示的实际价值 |

## 3. 任务清单（每用户约 20 分钟）

1. 静听 2 分钟系统播报，说出听到了什么（检验播报可懂性）
2. 沿盲道行走 30 米，系统在旁提示（检验盲道/障碍播报时机）
3. 口头向系统提问"前面有什么""能过马路吗"（语音输入链路）
4. 说一次"说慢一点"，确认语速变化符合预期
5. 开放性提问：如果每天用，你最想要什么/最烦什么？

## 4. 观察与记录指标

| 指标 | 记录方式 |
|---|---|
| 播报可懂率 | 用户复述正确的播报比例 |
| 播报时机评分 | 1-5 分：太早/正好/太晚 |
| 告警打扰度 | 每次用户表达"太吵/打断说话"即计数 |
| 任务完成情况 | 各阶段独立完成/需陪护提示 |
| 关键引语 | 原话记录 3-5 条（答辩可直接引用） |

## 5. 记录表模板（每位用户一份）

```
用户编号：U__   日期：____   视力状况：____
阶段A 可懂率：__/10   语速反馈：____
阶段B 完成情况：独立/需提示   打扰计数：__
阶段C 完成情况：独立/需提示   红绿灯提示有效性：1-5
最有用的一次播报：________________
最困扰的问题：________________
原话引用：________________
```

## 6. 输出物（测试完成后一周内）

1. 一页汇总：可懂率/打扰度/典型问题分布
2. 3-5 条用户原话（答辩 PPT 素材，比任何功能列表都有说服力）
3. 改进清单：按"播报策略 / 检测类别 / 交互方式"归类，进入下轮迭代
