# BlindGuard 演示脚本

> 原则：现场只演示最稳的路径，翻车风险高的环节用预录视频兜底。
> 智能体占全程一半，是主角；检测与可靠性是支撑。
> 演示前一天必须跑一遍 `python smoke_test.py` 与完整流程。

## 一、时间轴总表（115 秒版）

| 累计 | 环节 | 关键动作 | 一句话目的 |
|---:|---|---|---|
| 0–15s | 开场 | 讲价值与差异化，不开演示 | 先立问题，再上技术 |
| 15–35s | 实时检测 | 上传视频，逐类框出，风险分级 | 证明感知真实可跑 |
| 35–100s | **智能体（主角，65 秒）** | 四幕：编排证据 → 规划 LLM → 安全拦截 → 多步帮助 + 展开驾驶舱 | 证明编排、自主、安全与可审计 |
| 100–115s | 收尾 | 架构图 + 证据一句话 | 落到工程可信 |

> 时间被砍时用第八节的 60 秒压缩版；已跑顺后可省掉第一幕补充（规划）压到 105 秒。

## 二、开场（15 秒）——先讲价值，再开演示

> "全球有 2.85 亿视障人士，传统盲杖只能探知身边一米。
> 市面上的 AI 助盲工具，比如 Seeing AI，都是'用户举手机拍照'的被动模式。
> BlindGuard 是主动式：系统持续盯着环境，发现风险主动开口提醒——
> 并且我们针对中国道路定制了井盖和盲道检测，这是通用模型不认识的。"

（这一段同时回答了"创新点"和"与竞品差异"两个必问问题。）

## 三、环节 1：实时检测与风险分级（20 秒）

- 启动系统 → 上传演示视频
- 指着画面说：汽车、井盖、盲道、红绿灯逐个框出；右侧面板风险等级实时变化
- 强调："这是我们自己训练的 6 类模型，井盖和盲道是通用 YOLO 不认识的"

## 四、环节 2：智能体（65 秒，全场核心）

### 第一幕：编排与证据（20 秒）

输入"**前面有什么危险？**"，然后**只讲屏幕，不讲代码**：

1. 指着回复气泡下方的**编排链路**条：6 个阶段（意图路由 → 本地预取 →
   角色协作 → 模型推理 → 工具循环 → 安全复核）逐个亮起
2. 念出"**决策依据**"那一行，说明每一步都有理由
3. 点开"**角色与工具明细**"：哪个角色读了哪个工具、耗时多少

> 话术："LLM 只是这条链路上的一环，不是决策权威。
> 每一轮对话都留下阶段轨迹、角色结论和工具轨迹，可以逐条核对。"

### 第一幕补充：让规则"认不出来"，展示 LLM 参与任务分解（10 秒）

用一条规则路由识别不了的自由提问（例如"**帮我看看现在是什么情况**"）：

- 链路条上会出现绿色的"**规划 LLM**"标签（规则命中时是灰色的"规划 规则"），
  下面多一行"**规划依据**"，写明模型给出的理由与指派角色
- 点名一句："规则没认出来的请求，模型会做任务分解——但它**只能选角色，
  不能选工具**，工具由角色表推导，所以计划和实际执行永远对得上"
- 若想展示降级：把模型端点断开再问一次，"规划"会变回"规则"，链路照常走完

> 这一条直接回答"是不是只是 if-else"：规则快路径 + 模型慢规划，
> 而且模型的提议必须通过本地白名单校验才执行。

### 第二幕：安全拦截（20 秒）

输入"**现在能过马路吗？**"

- 指出红灯、黄灯、未知灯态或高风险时系统**直接本地拒绝，不等待 LLM**；
  这条回复的链路里"模型推理"是灰色"**绕过模型**"，肉眼可见
- 若画面是绿灯，回答也只会说明"不能确认路口安全"，不会授予通行许可
- 看**安全复核**卡：橙色高亮的那句就是守门员追加的保守说明，
  上面的灰框是模型原始回复——"改了什么"一眼可见

> 话术："大模型没有通行授权能力。它的输出会经过本地确定性复核，
> 出现'可以通行''放心走'这类措辞会被整句替换。"

### 第三幕：拒绝授权 ≠ 拒绝帮助（10 秒）

输入"**现在能过马路吗？不能的话我该往哪边站**"

- 先确定性拒绝通行，再用导航员工具补一段方位与避障建议
  （"当前方位：左侧汽车…停在当前位置…"）
- 明细里能看到多出一条 `get_navigation_guidance` 角色调用

> 话术："**拒绝授权不等于拒绝帮助**——它照样告诉你往哪躲，
> 只是永远不说'可以走'。"

### 第四幕（可选，5 秒）

输入"**说慢一点**"——展示 TTS 语速真实变慢、偏好持久化。

> 一句话收束："LLM 负责理解和表达，确定性安全层负责拒绝授权。"

## 五、环节 3：可靠性（并入智能体，见第三幕后的断网演示）

- 断网（或飞行模式热点切换），继续提问——展示离线兜底模板照常工作，
  且链路里会出现"**模型未应答，本地兜底**"标记
- 一句话："LLM 连续失败自动熔断 30 秒，网络恢复自动重连，
  全程检测与播报不中断——辅助残障人士的系统，可靠性优先于智能。"

> 这个标记本身就是证据：我们不会把兜底回答伪装成模型作答。

## 六、收尾（15 秒）

- 切到架构图：检测 → 红绿灯/跟踪 → 风险 → 场景 → Agent → 语音
- 收尾语："单实例检测管线，多端共享；10 个角色有职责与权限边界，
  13 个工具有限权限时与审计；104 项回归测试、12 项 Agent 运行时审计全通过。
  哪些已验证、哪些还没验证，我们都写在了一页纸证据上。"

## 七、问答环节：切到「智能体架构」面板

侧边栏「智能体架构」卡片点开即是台账，用于回答"多智能体是不是真的"：

- **10 个角色**：每个都带职责说明和**权限边界**（如"只描述观测，
  不推断未检测到的安全"），并用标签标出本轮**已执行 / 待命 / 未参与**
- **13 个工具**：逐个标出「只读 / 可写」「常规 / 用户数据 / 安全语境 / 外呼」
  和各自的超时上限——写工具与外呼工具都受权限约束
- **最近调用审计**：真实调用记录（成功率、耗时、超时、错误原因）；
  越权调用会让概览里的"**最近策略拒绝**"变红并计数

> 标准话术："我们故意不做角色自由对话——安全系统要可预测、可审计。
> 每个角色有职责、有权限边界、真实执行、留下结构化证据。"

配合 `docs/答辩一页纸.html`（浏览器打开即可投影，也可打印为 PDF）使用。

| 累计 | 内容 | 舍弃 |

## 九、翻车预案

| 风险 | 预案 |
|---|---|
| 现场网络不通，LLM 不回复 | 链路会显示"模型未应答，本地兜底"——顺势演示可靠性，话术："我们连断网都是功能" |
| 摄像头打不开 | 主用上传视频演示，摄像头作为加分环节 |
| 端口占用/环境异常 | 提前 `python smoke_test.py`；备用机同环境克隆一份 |
| 演示视频丢失 | uploads/video.mp4 提交到演示 U 盘 + 网盘双备份 |
| 评委要求现场输问题 | 只答"能过街/不能过街"类问题最稳；自由提问时先看一眼链路条的"意图"是否符合预期 |
| 追问实时指标 | 直接给一页纸证据的"诚实边界"段，不即兴给数字 |
