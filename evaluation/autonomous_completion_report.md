| 专业角色真实执行 | 通过，感知、风险、导航、沟通和安全角色产生结构化证据 |

最终结果：`12 passed, 0 failed`。Agent 状态为
`llm_active=true`、`fallback_active=false`、`tools_supported=true`、
`agent_version=2.5.0`、`orchestrator_version=1.1`、`role_count=10`、
`tool_count=13`、`tool_prefetch_enabled=true`、
`specialist_execution_enabled=true`、`max_model_tool_calls=6`。

因此可以确认：

**智能体协议、专业角色编排、有界工具预取、真实模型推理、工具调用、最终回答
和安全后处理已经形成闭环，不再是纯模拟。**

当前智能体采用“编排式专业团队 + 确定性安全守门员”架构。LLM 只是编排循环
中的一个能力，不是通行决策权威：

- `safety_guard`：最高优先级安全守门员，覆盖 LLM 输出，但不得授权通行；
- `perception`：读取目标、方位、置信度、跟踪趋势和灯色，只描述观测；
- `risk_analyst`：输出风险排序、原因和优先避让对象；
- `navigation_advisor`：生成停步、减速、盲杖确认等非通行建议；
- `temporal_memory`：聚合同一目标的出现、消失、接近、远离和灯色变化；
- `visual_observer`：按需调用 VLM 查看文字、标志和检测框外细节；
- `preference`：读取和调整白名单内的语速、播报详略等偏好；
- `communicator`：把工具结果压缩成简短自然的中文回复；
- `alert_manager`：综合风险、置信度、紧急度、冷却和播报历史决定是否主动播报；
- `self_monitor`：报告模型、工具、视觉、降级和最近工具轨迹。

13 个工具由统一注册表管理 JSON Schema、读写权限、安全级别、超时、参数校验、
结果归一化和调用审计。除原有检测、场景、记忆、风险、偏好、健康和历史工具外，
本轮新增 `get_navigation_guidance` 与 `get_alert_policy`。前者明确不包含过街
授权，后者明确静默只代表未达到播报门槛。

本地意图路由覆盖偏好、能力、系统健康、播报历史、视觉、时序和环境七类路径；
进入 LLM 前最多预取 2 个本地只读工具，降低模型幻觉和往返延迟。主责与协作
角色随后基于真实工具结果产出结构化结论，写入 `role_contributions`。外部 VLM
永不自动预取，只有模型在明确视觉意图下才可按需调用。预取轨迹标记为
`phase="prefetch"`，角色补齐的工具标记为 `phase="specialist"`，模型真正发起
的调用才进入 `llm_tool_loop`，三类证据不会混写。同轮成功只读工具进入缓存，
重复读取标记 `cache_hit=true`；累计工具调用最多 6 次，越权写入和非视觉意图
外呼 VLM 会被拒绝并记录 `policy_denied=true`。每次对话还记录
`routing -> prefetch -> specialists -> llm -> tool_loop -> safety_review`
阶段轨迹；安全复核不再做自比较，而是保留原始回复、最终回复、是否真正改写、
最终是否仍含危险授权措辞以及二次复核是否幂等。

在线证据：[agent_runtime_audit_online.json](agent_runtime_audit_online.json)

真实执行、模型工具权限策略、导航建议安全边界、播报策略可解释性、工具循环

因此当前应用状态仍可能是：

- `llm_configured=true`
- `llm_active=false`
- `fallback_active=true`
- 页面显示“本地回退”

这不是程序崩溃，而是在线模型不可用时的预期降级路径。在线失败不会阻止
检测、风险判断、模板播报和本地对话继续运行。

### 1.7 安全策略

单元测试覆盖并通过：

- 红灯、黄灯、未知灯和高风险场景不向 LLM 请求通行许可；
- 绿灯只做描述，不输出“可以走”；
- 无检测结果不能推断安全；
- 危险 LLM 回复被替换；
- 即使不是过街提问，回复中出现“可以通行/放心走”等授权措辞也会被拦截；
- 安全审计字段能证明发生真实改写，最终回复不含危险授权且二次复核幂等；
- 红灯主动播报走本地模板；
- 通用环境问题仍可执行工具调用。

完整说明见 [安全策略.md](../docs/安全策略.md)。

## 2. 环境限制

以下限制来自外部服务、硬件、授权数据或部署配置，当前不能由代码单独消除：

1. **DeepSeek 无余额**：在线端点返回 HTTP 402，当前正式配置无法完成真实
   在线聊天验证。
2. **VLM 未配置**：`look_at_frame` 没有可用的多模态视觉端点，因此当前真实
   VLM 看图能力未完成验证。
3. **本地模型不是生产配置**：Qwen 2.5 3B 通过 Ollama 验证了 Agent 协议和
   工具闭环，但它是本地测试模型，不等同于已部署的线上服务，也受本机算力、
   模型许可证和长期稳定性约束。
4. **麦克风硬件未验证**：自动化只验证了语音按钮调用和状态切换；真实麦克风
   权限、浏览器语音识别、噪声环境和 Whisper 转写仍需人工设备测试。
5. **端到端检测指标尚缺**：现有 mAP 和灯色准确率来自离线数据或裁剪图，
   不能代表当前双模型、960 px、竖屏裁剪配置在连续实拍中的精确率和召回率。
6. **没有真实路口授权数据**：不能自动生成第一人称盲人行走数据，也不能在没有
   陪护和授权的道路上做安全验收。
7. **CI 与客户端回归范围有限**：自动审计覆盖了本机 Chromium 和当前视频，
   未覆盖所有手机浏览器、WebView、弱网和长时间运行场景。

## 3. 必须人工参与

这些工作不能靠当前自动化代替，也是从“优秀工程原型”进入“可信国奖项目”
所缺的核心证据：

1. **真实视障用户测试**
   - 建议至少 5-8 位全盲或低视力用户；
   - 必须包含知情同意、陪护和随时终止机制；
   - 记录任务完成率、错误授权次数、响应延迟和主观可用性；
   - 方案已存在：[用户测试方案.md](../docs/用户测试方案.md)。

2. **第一人称 POV 数据采集与标注**
   - 需要头戴、胸前或导盲设备真实视角；
   - 需要合法授权、脱敏、场景隔离和逐帧或关键帧标注；
   - 规范见 [pov_data_collection.md](../docs/pov_data_collection.md)。

3. **当前部署配置的端到端准确率**
   - 固定模型 SHA256 和管线配置；
   - 统计漏检、误检、类别混淆、距离误差和灯色错误；
   - 不能拿 BDD 或 COCO 的离线 mAP 代替。

4. **真实路口与过街验收**
   - 必须在封闭或受控环境中由陪护人员执行；
   - 核心指标是“错误授权次数”，目标必须为零；
   - 同时记录漏报、误报、延迟和用户能否正确理解语音。

5. **真实语音链路测试**
   - 测试安静、车流、风噪、多人交谈等环境；
   - 覆盖浏览器权限拒绝、断网和识别失败；
   - 验证朗读速度、中断、重试和紧急告警优先级。

6. **多设备与长时稳定性**
   - 覆盖常用 Android WebView/Chrome、iOS Safari 和目标硬件；
   - 进行至少 30-60 分钟连续运行、内存和温度回归。

## 4. 功能缺陷结论

当前自动化能够覆盖的前端按钮、状态恢复、视频控制、键盘操作、响应式布局、
摄像头管线和 Agent 工具闭环均未发现阻断性 bug。

仍存在以下残留下沉风险，不应写成“已经完全落地”：

- 当前正式配置的 DeepSeek 在线请求不可用，应用实际走本地回退；
- 真实麦克风转写和 VLM 看图没有完成设备验证；
- 连续真实视频的端到端准确率、真实路口安全性和视障用户有效性尚缺证据。

智能体可以评价为：

**已真实落地到专业角色编排、统一工具注册表、有界只读预取、协议、工具调用、
本地模型推理、安全改写和离线降级层面；
尚未完成线上生产模型、多模态视觉和真实用户场景的可用性验收。**
